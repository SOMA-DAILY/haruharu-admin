# 방 활동 조회 (#29, #68, #70, #72)

`/sessions/:id`의 방 활동 화면. 기존 관리자 조회 API를 사용한다. 참여자 사진은 방 상세의 nullable `members[].profile_image_url`을 사용하며 DB 스키마 변경은 없다.

## 현재 화면

- 영상 모아보기가 기본이다. 전체 활동·채팅·반응·질문 단독 탭과 기존 무한 스크롤/더 보기를 유지한다.
- 상단은 일차·참가자 필터와 간단한 건수만 표시한다. 기존 참가자별 숫자 표는 화면 아래에서 펼쳐본다.
- 표의 참여자 열 바로 오른쪽에는 44px 대표 프로필 사진을 블러 없이 표시한다. 클릭 또는 Enter/Space로 원본 비율의 사진을 확대하며 Escape로 닫는다. 사진 없음·불러오기 실패는 같은 크기의 `—`로 처리한다. 확대 중에는 영상 시간 이동 단축키를 적용하지 않는다.
- 영상 영역에는 두 시간대가 완전히 보이도록 각 구역을 영역 높이의 절반으로 맞춘다. 시간대별 영상 구역을 세로로 쌓는다. 6/8/10명은 2행×3/4/5열이며 참가자 자리는 업로드 유무와 관계없이 고정한다. 참가자 필터는 영상 자리 강조와 채팅 필터에 적용한다.
- 썸네일과 재생은 원본 전체가 보이는 contain 비율이다. 모달에서 재생·전체화면이 가능하고, 닫으면 플레이어를 해제한다.
- 참가자 ID·정확한 업로드 시각은 툴팁에 둔다. 기본 화면에는 이름·영상·필요한 상태만 표시한다.

## 연속된 채팅과 시간 이동

- 영상 옆에는 선택한 기간의 그룹 채팅 전체를 발생순으로 유지하는 독립된 채팅창이 있다. 영상 시간대가 바뀌어도 메시지를 해당 시간대로 필터링하거나 채팅창을 교체하지 않는다.
- 영상 영역에서 ←/↑는 이전, →/↓는 다음 시간대로 한 칸씩 이동한다. 첫/마지막 경계에서 멈추며, 채팅·입력·드롭다운·팝오버·영상 모달의 키 입력은 가로채지 않는다.
- 영상을 스크롤하거나 시간대 선택/이전·다음 버튼으로 이동하면 채팅창 안에서 해당 시간대 첫 채팅으로 스크롤한다. 이전·이후 대화를 그대로 읽을 수 있다.
- 대화창을 직접 스크롤해도 영상은 움직이지 않는다. 헤더의 연동 아이콘으로 자동 연동을 끄거나, 위치 아이콘으로 현재 영상 시각에 다시 이동한다.
- 채팅 없는 시간대는 다음 채팅으로 이동한다. 이후 채팅이 없으면 마지막 채팅 시간대에 둔다. 해당 시간대에 채팅이 없다는 짧은 상태만 표시한다.
- 영상 정렬을 최신순으로 바꿔도 채팅은 발생순이다. 일차·참가자 필터를 바꾸면 해당 조건의 연속된 채팅을 다시 구성한다.
- 반응·질문은 채팅에 섞지 않는다. 영상 시간대 헤더에 있는 아이콘·건수를 누르면 상세를 펼쳐본다. 반응은 누가 누구에게 남겼는지와 대상 영상 바로가기를 제공한다. 질문은 현재 답변을 함께 표시한다.

## 데이터

기존 `GET /rooms/{id}/activities`, `GET /rooms/{id}/activity/summary` 및 방 상세 API를 재사용한다.

- 시간대별 보기는 선택한 일차/전체 기간의 모든 활동 페이지를 size=100, order=asc로 끝까지 조회한 뒤 표시한다. 중간 페이지 실패·페이지 불일치·총 건수 변경·중복 제거 후 건수 불일치를 빈 영상/0건으로 숨기지 않는다.
- 전체 시간대 목록을 재사용하므로 참가자 필터만 바꾸면 같은 데이터를 다시 내려받지 않는다. 캐시는 일차별 60초이며 새로고침으로 갱신한다. 취소 신호는 HTTP 요청까지 전달한다.
- 영상은 slot_start, 채팅·반응·질문은 occurred_at 기준이다. 신규 방은 starts_at 상대 1시간 슬롯/24시간 일차, 구형 방은 09시 경계를 따른다. 늦게 완료된 영상도 원래 슬롯에 놓는다.
- 시작 전 미래 슬롯은 만들지 않는다. 시작 후 빈 시간대와 기간 외 데이터도 유지한다. 참가 전/업로드 종료를 미업로드와 구분한다.
- 반응은 현재 남아 있는 상태이며 취소·교체 이력이 아니다. 질문 답변도 현재 상태다. 운영자 권한과 서명 URL 만료 계약은 기존과 같다.
- 사진은 기존 대표사진 일괄 조회와 원본 이미지 URL 발급을 재사용한다. 이전 서버 응답에 사진 필드가 없어도 표를 표시한다. 활동 새로고침 시 방 상세도 갱신하여 사진 주소를 다시 받는다.
- 운영 데이터·테스트 데이터를 섞지 않으며 제품에 목업/인증 우회를 넣지 않는다.

## 검증

Node 22에서 `npm test`, `npm run lint`, `npm run build`를 사용한다. 모델 테스트는 고정 열 수·일차/시간 경계·늦은 업로드·빈/미래/기간 외 시간대·연속 채팅 이동/빈 시간대/참가자 필터를 확인한다.

독립된 로컬 QA 스키마와 기존 관리자 서버, 실제 API를 연결해 Chromium에서 검증한다. 6/8/10명 방(영상 231/312/387, 채팅 각 184개), 한 시간에 140개 메시지, 반응·질문·답변을 사용한다. 연속 채팅 DOM/메시지 유지, 자동/수동 시간 이동, 독립 스크롤, 반응·질문 상세, 영상 재생/전체화면/해제, 필터·정렬·기존 단독 탭, 1024/1440/1920px, 중간 페이지 실패/재시도를 확인한다.

증거는 워크스페이스 `artifacts/admin-room-insights-20261023/revision-results.json` 및 revision-final-*.png에 기록한다. 운영 배포/실제 운영 S3/Safari/Firefox는 미검증이다.

참여자 사진 추가 검증은 `artifacts/admin-participant-photos-20261023/browser-results.json`에 기록한다. 로컬 API/DB의 6/8/10명 표, 원본 세로/가로 비율 확대, 키보드/닫기, 확대 중 시간 이동 방지, 이전 응답 호환, 사진 없음/404, 일별 합계 및 1024/1440/1920px을 확인한다. 사진 추가분의 운영 배포와 실제 운영 S3 접근은 별도 확인 대상이다.

참여자 표 헤더와 사진 확대 도구 영역의 `사진 블러` 스위치로 썸네일·확대 사진의 블러를 함께 전환한다. 기본 OFF이며 화면 안에서만 적용된다. 새로고침하면 OFF로 시작한다. 원본 URL·서버 데이터·일반 앱의 사진 공개 정책은 변경하지 않는다. 스위치의 클릭/키보드는 표 접기나 영상 시간 이동을 실행하지 않는다.

블러는 앱 프로필 시트의 iPhone 12 표시를 기준으로 한다. 64pt 사진을 @3x(192px)로 먼저 축소하고 expo-image가 blurRadius 12의 절반인 6px를 적용하므로, 웹에서는 원본 비율을 보존해 긴 변을 최대 192px로 줄인 사진에 6px 블러를 적용한 것과 같은 비율을 사용한다. 정사각형 썸네일의 cover 잘림과 192px보다 작은 원본도 계산에 반영한다. 썸네일과 원본 확대 모두 이 비율을 유지하고, 창 크기 변경 시 재계산한다. 확대·축소·회전은 이미지와 블러에 함께 적용된다. 네이티브와 브라우저의 필터 구현 차이 및 Android의 별도 블러 처리로 픽셀 단위 결과까지 같음을 보장하지는 않는다.
